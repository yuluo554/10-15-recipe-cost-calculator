## 一之二、M0 数据底座复核（2026-10-15 实测，接口参数勘误）

**历史日期查询可用**（这是"多期快照"模块的可行性前提）：

- 请求参数为 **`pubDateStartTime` / `pubDateEndTime`**（形如 `2026-08-06`），**不是** `startDate`/`endDate`。
  实测 `startDate`/`endDate` 被接口忽略、返回最新一期数据（日期仍为 2026-10-14）——**若按此实现会静默拿到同一期数据，两期快照退化成同一期**。
- 实测三日期取回的大白菜均价与题面一致：2026-08-06 = 0.55 / 2026-09-06 = 0.53 / 2026-10-06 = 0.40（元/斤）。

**品类 id 实测**（`prodPcatid` 参数）：

| id | 品类 | 单日记录数（2026-10-14 实测） |
|---|---|---|
| 1186 | 蔬菜（含水菜） | 132 |
| 1187 | 水果（梨/柑橘/桃李杏/西瓜/香蕉/甜瓜/苹果/葡萄/芒果） | 86 |
| 1189 | 肉禽蛋（猪肉/牛肉/羊肉/禽蛋） | 141 |

（1188 / 1191 / 1192 实测返回 0 条，不采用。）

**`prodName` 过滤勘误**：题面注记"prodName 过滤无效需用 prodPcatid"**只在单独使用 prodName 时成立**——实测 `prodName` + `prodPcatid` **组合**过滤有效（返回指定品名的多日记录）。M0 据此修正题面表述。

**抓取纪律**：快照入库须记录抓取日期、URL、原始响应文件名 + sha256；快照文件只增不改（`.gitattributes` 已标 `data/snapshots/** -text` 防 EOL 改写字节），两期对比用不同文件。

## 一之三、M1 快照抓取留档（2026-10-15 实测）

快照已入仓，共 **3 个可区分数据日**（题面三个实测点）。台账（含抓取日期 / URL / 原始响应文件名 / sha256 / 记录数 / 品类覆盖）在 `data/snapshots/ledger.json` 与 `data/snapshots/README.md`，二者由抓取器 `tools/fetch_snapshots.py` **同源渲染**（禁手改；手改即被 `--check` 检出）。

| 数据日 | 记录数 | 品类覆盖（蔬菜/水果/肉禽蛋/水产） |
|---|---|---|
| 2026-08-06 | 467 | 134 / 81 / 140 / 112 |
| 2026-09-06 | 327 | 104 / 83 / 140 / **0** |
| 2026-10-06 | 474 | 133 / 87 / 141 / 113 |

三个数据日的**大白菜 avgPrice 直接从留档件读出**为 0.55 / 0.53 / 0.40 元/斤——与题面 §12 实测点逐位一致，即题面论证可由入库快照复算，不靠外部记忆。

**抓取期实测的三条接口陷阱（已写进抓取器断言，防复现）**：

1. **`limit` 缺省会静默截断到 20 条**——响应 `count` 仍是真实总数（如 467），但 `list` 只回 20 条。抓取器因此显式给足并**断言 `len(list) == count`**，否则快照会悄悄缺记录而 sha256 依然"自洽"。
2. **请求参数会被响应原样回显**（`current`/`limit`/品类 id 都在响应体里），故参数集必须固定——同一数据日换 `limit` 值即得不同字节，sha256 不可比。抓取器把参数集记进 `.meta.json` 的 `request` 字段。
3. **整日全品类查询与逐品类求和逐条集合相等**：实测整日一次查询（467 条）的 `id` 集合 == 四个品类分别查询求和的 `id` 集合。抓取器取"整日一次查询"为留档主体，另以逐品类查询**交叉核验覆盖**（断言并集 == 整日记录数），不等即报"有品类未登记"。

**两条必须知道的数据形态（不隐藏）**：

- **`prodName` 同日可重复**：467 条里只有 394 个不同品名（73 条重复），重复项是**不同规格/产地**（如"平鱼"4 条、土豆 2 条）。引擎 `load_snapshot` 按品名建索引，**后出现者覆盖前者**——这是既有的确定性行为，但意味着"按品名取价"隐含"取该品名最后一条"的语义。原始件保留全部条目，重复条数逐日记在 `.meta.json` 的 `duplicate_prodname_count`。
- **单位不全是"斤"**：467 条里 454 条为斤，其余为个/只/筐/箱（如"筐鸡蛋"按筐计价）。快照 `.meta.json` 的 `unit` 字段是**多数单位**，逐条单位以原始件 `unitInfo` 为准；首期不做单位换算（列扩展项）。

**`data_date` 与 `captured_date` 是两个字段，不是一回事**（M1 实测暴露的缺陷，已修）：

- `data_date` = **数据日**（行情所属交易日），是"两期快照"的**期间标识**；
- `captured_date` = **抓取日**（留档可复现性），同一抓取日可抓多个数据日。

M0 期的 `load_snapshot` 把 `date` 映射到 `captured_date`，于是两期不同数据日会**双双显示成同一个抓取日**——期间在输出里不可区分，正是"两期退化成同一期"的**第二种形态**（第一种是 `startDate` 参数被忽略）。已改为 `date` ← `data_date`，并在 `engine/pipeline.py::compute_alert` 加**两期数据日相同的显式拒绝**（exit 2，不静默产出"全平"假结果）。

**复核命令**（`--check`/`--selftest` 全离线且随测试常驻）：

```bash
py -3.12 -X utf8 tools/fetch_snapshots.py --check          # 重算 sha256 + 台账同源一致
py -3.12 -X utf8 tools/fetch_snapshots.py --selftest       # 阳性/阴性对照（篡改必被检出）
py -3.12 -X utf8 tools/fetch_snapshots.py --refetch-check  # 联网重抓比对字节（人工跑）
```

**抓取器在 `tools/` 而产品"不联网拉价"**：抓取是**开发期一次性动作**，产出的快照随包冻结；运行期产品只读冻结快照，README"限制"节的口径不变。

## 三、合成数据纪律

- 演示/样例数据一律合成，禁止使用真实门店/真实经营者信息。
- **假店名白名单**（样例进货单/演示数据专用）：`示例食堂甲`、`示例小馆乙`、`示例快餐丙`。白名单外新增须先在此登记。
- **真实价格数据**：仅使用新发地公开批发价快照，逐份记录抓取日期；真值表中的价格字段必须可追溯到快照文件。
- 合成真值由确定性引擎程序化生成并植入期望输出，禁止手写期望值。
- 覆盖度口径：各基准套件按模块（导入/换算/定价/预警）列最低覆盖项，写入 plan/03 与 plan/00 台账，防真值偏科。

### 三之二、进货单样例的三态演示职责（M2 登记）

`data/samples/purchases-demo.csv` 由 `tools/gen_samples.py` 生成（**禁手改**，改需求走生成器整目录重生成 + `--check`）。它不只是"能跑通"的输入，而是**导入三态的演示载体**——刻意注入每一类异常，否则三态矩阵在样例上不可见：

| 注入项 | 演示的语义 |
|---|---|
| 未登记列名「备注」（表头级） | `unknown`（`mapping_uncertain`），**行仍可用** |
| 字段数多于表头（行级） | `unknown`（`structure_unparsable`），**行不入库** |
| 数量非数值 / 品名为空 / 数量为负 | `invalid` 三种触发 |
| 单位「克拉」 | `unknown`（单位未登记），**行仍可用** |
| 同品名二次进货（土豆） | **非异常**——让"食材库取最后一条价"的取舍可观测 |

`tests/unit/test_csv_import.py` 有对应用例断言"样例覆盖全部异常类"，故**删掉任一注入行都会使测试变红**——样例不会被悄悄简化成"只有正常行"。

## 四、口径纪律

数值口径（净料单价公式、毛利率反推公式、四舍五入规则、波动预警阈值默认值）**只在一处定义**（plan/02 算法与口径说明 + `src/rcc/rules/formulas.py`），本文件与题面注记均为引用，不得手写第二份口径。默认值（损耗率、预警阈值等）均为经验示例值，注明非官方出处。
