### M4 期（基准：五套件达标 + 探活全红 + 覆盖度如实声明）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **真值库只存输入与期望，观测在运行时实算** | 若把观测也冻进真值库，评测就退化成"比对两个冻结字典"——**引擎坏掉也照样全绿**，那正是本项目最忌的假门（"基准全绿"可能只是"基准什么都没查"）。故 `data/truth/*.json` 只含 `input` + `expect_keys`，观测由 `benchmark/cases.py::observe_*` 把输入**真喂引擎**后实算。守门 G-TRUTH-FROZEN 断言真值库里没有 `observed` 一类字段 |
| 2026-10-15 | **结论键自带结论**（键名编进结论，取值恒 `ok`） | 只把状态当值（`{"status:X": "up"}` vs `"down"`）时**字段名集合相同**，集合对账看不见差异——**误分类会静默通过**。改为键名自带结论（`status:X=down`、`cost:X=3.24`），值的变化即改变键名，"漏一个 + 多一个"同时暴露。对账语义仍单一实现源（`benchmark/cases.py`） |
| 2026-10-15 | **覆盖度分母从代码常量集反射，分子必须等于分母** | "只写分子即假覆盖"（plan/03 §四）在实现里还差一步：**分母从哪来**？M4 把 B1/B2 的分母定为 `csv_import`/`pipeline` 的 `ISSUE_*` **运行时反射**结果 + 登记的结构性形态，且**新增代码而无用例 → 生成器直接报错**（`TRUTH_FORMS_INCOMPLETE`，exit 1）。于是"悄悄做小分母"这条路被堵死。**判别口诀：凡"覆盖率 100%"，先问分母是不是被我做小了** |
| 2026-10-15 | **时长门槛真参与判定；误报率要么实测要么显式声明未测** | `max_duration_seconds` 原先**登记在门槛里却既未校验也未使用**（"登记了却静默不判"）。M4 按"实测耗时 ≤ 门槛"判定。误报率同理：样本驱动层是**实测值**（观测多出的结论键占比），写死 0 再比门槛是恒真假门；规则驱动层（B4/B5）无观测键通道、**结构上不可测**，故由 manifest 的 `measures_false_positive` **显式声明未测**——登记比沉默好 |
| 2026-10-15 | **B4 量化探活补硬** | 原探活只断言"坏实现本身给出不同结果"，**没断言套件报未达标**——那不是探活，是对坏实现的自述。M4 改为断言 `suite_boundary(...)["ok"] is False`，并保留"坏实现确实与正本不同"作为前提断言（防恒真假门） |
| 2026-10-15 | **共同验收门统一到 `FROZEN_TRUTH_OK`** | plan/02 §七 与 plan/03 §二 表述不同（前者 `FROZEN_TRUTH_OK`、后者泛指 `OK`）。按"plan/02 是口径来源"统一为三生成器各输出 `FROZEN_PARAMS_OK`/`FROZEN_SAMPLES_OK`/`FROZEN_TRUTH_OK`，并回写 plan/03 §十一 |

### M5 期（交付：免安装 exe + 随包数据可自证）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **`build_datas()` 对目录条目取"条目自身"作目标目录（不是 `dirname`）** | 实装 spec 时发现白名单里的三个**目录**条目全用 `dirname(rel)` 作 dest，而 PyInstaller 把目录源的**内容**复制进目标目录 → `data/snapshots/x.json` 会变成 `data/x.json`（**拍平**），三份快照连 README 一起挤进 `data/`。构建**不报任何错**，源码态照跑，冻结态按 `data/snapshots/` 取数才落空。处置 = 目录取条目自身、文件取父目录，并把"包内路径 == 仓库内相对路径"写成 G-PACK 的**核心断言**（不是断言"某处没写某字符串"） |
| 2026-10-15 | **冻结态数据定位收敛到 `find_data_dir()` 单一入口** | `benchmark/runner.py::TRUTH_DIR` 与 `cases.snapshot_path()` 原先各按 `__file__` 上溯拼 `data/...`——源码态对，冻结态指的是**不存在的"仓库根"**。处置 = 两处都经 `find_data_dir()`：runner 用 `find_data_dir()/truth`，cases 用 `dirname(find_data_dir())/data/snapshots/...`。**"数据在哪"与"数据怎么装进去"是同一条口径的两面**，分成两处就是第二份真相 |
| 2026-10-15 | **两个 exe 的 datas 全传 COLLECT，不靠"两边恰好相同"** | PyInstaller 的静态分析跟进函数体内 import（`cli → cmd_gui → gui.main_window → PySide6`），故 CLI 与 GUI 两个 Analysis **各自都收集了一份 Qt datas**（插件/翻译）。只传 `a_cli.datas` 实测能出可用包——但那是在赌两个分析恰好收集同样的文件；哪天 GUI 侧多收集一个，它会静默不进包。处置 = 两边 datas 都传，去重交给 COLLECT |
| 2026-10-15 | **启动器独立成 `tools/launcher_cli.py` / `launcher_gui.py`，不拿 `src/rcc/cli.py` 当入口** | PyInstaller 把入口脚本当**顶层模块**执行，`cli.py` 里的 `from . import __version__` 这类包内相对导入会直接 ImportError。启动器只装编码守卫 + 转交包内 `main`，**零业务判断**（判定逻辑留在包内，否则同一判断会长出第二份实现） |
| 2026-10-15 | **窗口版的页签数在启动器里观测，不进 `rcc.selftest`** | `--selftest` 的核心自检属**核心层**，若让它 import GUI 观测页签，就等于把 PySide6 拖进 CLI 的导入图——与"重件只在函数体内 import"的分层纪律相悖，`rcc selftest` 会在没装 gui extra 的机器上挂。处置 = 核心自检零重件（恒跑），页签装配的观测落在 `launcher_gui.run_selftest()` |
| 2026-10-15 | **G-PACK 门落 `tests/guards/test_pack_gate.py`，判据是"布局可达"而非"字面干净"** | spec 静态扫（无手写数据路径 / 无禁区字面）+ AST 断言 `DATAS` 由 `build_datas()` 产生 + **行为断言**：白名单产物经 PyInstaller 语义展开后，包内路径必须等于仓库内相对路径；外加构建前白名单对账与冻结态判定本身的探活。**"spec 里没有某字符串"只证明写法合规，证明不了打出来的包能取到数据** |

### M6 期（发布：公开仓库 + 确定性产物 + 三件套）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **`benchmark/` 必须进安装面：`package-dir` 显式映射其根** | **M6 头号发现**。干净环境验证抓出：`benchmark/` 在仓库顶层，而 pyproject 只声明 `package-dir = {"" = "src"}` + `where = ["src"]` → 它**根本没被装上**。三种运行方式里**只有控制台脚本会挂**：源码态仓库根 `python -m rcc.cli bench` 能过（CWD 在 `sys.path` 上）、冻结态 `rcc.exe bench` 能过（PyInstaller hiddenimports 显式收了它）、**装好的 `rcc bench` → `ModuleNotFoundError: No module named 'benchmark'`**。既有 G-README 门恰好用 `python -m` 形式，**也看不见它**。处置 = `package-dir = {"" = "src", "benchmark" = "benchmark"}` + `where = ["src", "."]`。**陷阱**：`where = ["src", "."]` 看着对，但默认根 `src` 会把 `benchmark` 映射到不存在的 `src/benchmark`，安装当场失败（已实测）——故必须给精确键。新门判定落在 **package-dir 的解析结果**上，并配探活复现那个坏配置 |
| 2026-10-15 | **release zip 的确定性只承诺"同 dist → 同 zip"** | `tools/make_release.py`：`ZIP_STORED` + 条目**按路径显式 sort**（`os.walk` 顺序跨调用不稳定，不排序则两次打包字节不同——**而两次都"成功"**）+ 全条目固定 `date_time=(1980,1,1,0,0,0)` + `create_system=0`。**exe 构建本身不承诺跨机字节一致**（PyInstaller 产物受 bootloader 构建、依赖版本、路径影响）——留档把 exe 那两行写明是"本机构建记录"而非"可复现"承诺。**"可复跑的是哪一步"必须写清**，否则读者会拿 exe 哈希去校验 |
| 2026-10-15 | **产物扫描的豁免裁决 = "官方原件同串比对"，且是实算不是清单** | 全 dist 树字节读法扫出 102 处 HARD（99 email + 3 idcard），**全部落在上游二进制**（CPython 组件 / OpenSSL / Qt），本项目自有数据与代码 **0 处**。裁决机制 = 命中串若在**运行本扫描器那条解释器的官方安装目录 + 其 site-packages** 中同串存在 → 判 `UPSTREAM`（**仍打印、仍计数**，只是不阻断）。**为什么不写豁免清单**：清单是"人写死的"，换依赖版本/换机器就与实况脱钩；同串比对是实算。**裁决有牙**（阴性对照实测）：注入一个不在上游的合成邮箱 → 仍判 HARD + exit 1。零 `user_path` 命中（个人路径按**组合签名**匹配，不匹配裸词——否则 Qt DLL 厂商串含用户名子串会刷屏） |
| 2026-10-15 | **审计器新增 `--dist-path`（产物在仓库树外）** | M5 纪律把构建产物放**仓库树外**（`--distpath` 指向 `$TEMP`，避开 `out/` 被 gitignore 的"看着成功其实没写"），而审计器的 dist 模式原本只认仓库内 `dist/`。二者叠加的后果 = **在正确的纪律下"产物扫描"扫了个空**。故支持显式路径，且在路径不存在时 exit 2 而非静默空扫 |
| 2026-10-15 | **sha256 留档去掉空行：GNU `sha256sum -c` 会对空行报 "improperly formatted"** | 哈希行仍由 `sha256sum` 输出**直接重定向**生成（手工转录 64 位 hex 错一位肉眼不可查），人只写注释行。但**留档里的空行会让 `sha256sum -c` 输出告警**——**刷屏的校验命令会让读者不再看它的输出**，与"误报会让门禁失效"同一条纪律。处置 = 去空行，`sha256sum -c` 复验输出三行全 `OK`、无告警 |
| 2026-10-15 | **新增 G-RELEASE 门（`tests/guards/test_release_tooling.py`）** | zip 确定性（两次打包 sha256 相同）+ 条目排序/固定时间戳/STORED 三条 + 随包数据不被拍平 + 构建后三断言（禁区成分 / 内嵌数据逐份一致 / 白名单外多余）各配**变异验证**。夹具用**程序化合成的迷你 dist 树**（不依赖 114MB 真产物），故可在 CI 常跑 |
| 2026-10-15 | **可见性 public 落地：`gh repo create --public` + SSH remote（不走 `--push`）** | 本机 token scopes = `gist, read:org, repo`，**无 `workflow`**——带 workflow 文件走 HTTPS+token 必被拒、留半失败态。故先建仓（不带 `--push`）→ `git remote set-url` 切 SSH → 一次 push 成（**SSH 不受 OAuth scope 限制**，携带 workflow 文件 GitHub 正常识别并触发 CI） |

## 五、纪律

- 不写会随实现漂移的硬数字（测试数/用例数/体积/通过数），指标只写口径与门槛来源；确需数字"以末态回填"。
- 数值口径一处定义（plan/02 + `rules/formulas.py`），注记与文档多处引用，禁止手写第二份口径。
- 每个"未挂来源"的参数不得进入计算路径。
- **诚实口径**：DoD 里的"CI 绿"在无远端时必须写成"本地等价校验，未接远端，CI 待首推验证"；**未推送 = 未跑 CI**，不得虚报。M0 期状态：**本地等价校验（本机实跑 pytest + 门禁 selftest）；CI 配置已入仓但未接远端，待首推验证**。
- **每个里程碑出口的硬约束**：DoD 验证 → plan/00·05·06 状态回写 → **写 `plan/HANDOFF-M<next>.md`** → commit →（有远端则 push 等 CI 绿）。"HANDOFF 已落盘"与"测试全绿"同属收尾 DoD。
- 品牌隔离：提及系列其他项目一律用**方向级描述**（工程技术类/财务合规类），不落具体领域名词。
