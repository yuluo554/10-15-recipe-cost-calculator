# plan/06 架构与技术选型

仓库 `10-15-recipe-cost-calculator`。v4（2026-10-15，M5 交付落地）。M0 定稿。

## 一、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.8+（本机通道 3.8.8 / 3.12.10） | 底线 3.8；CI 矩阵 windows×{3.8,3.12} + ubuntu×{3.12} |
| 核心依赖 | **零第三方**（纯 stdlib） | 引擎/解析/基准零依赖 → 结论 100% 可复现、基准离线可跑、脱敏面无外部调用 |
| 金额类型 | `decimal.Decimal` 全链路（`parse_float=Decimal`） | F4/F5 要检出 1 分差异，float 尾差不可接受 |
| 确定性 RNG | 自研 splitmix64（`tools/detrng.py`） | stdlib `random` 不承诺跨版本序列一致 |
| 报告 writer | 自写最小 OOXML writer | 第三方库的 ZIP 元数据（宿主系统标识/时间戳）会让字节漂移，破坏"同输入同字节"承诺 |
| GUI | PySide6（可选 extra） | 系列标准形态；GUI 只消费编排层 API |
| 打包 | PyInstaller **≥6**（onedir 双 exe） | 打 GUI 必须 ≥6（5.x 确定性崩）；发布构建固定用装了 ≥6 的通道（`py -3.12`） || LLM | **不使用** | 本领域是纯确定性规则 + 结构化输入，无"非结构化解析兜底"需求 → 全链路零 LLM（决策记录已登记） |

## 三、分层与单向依赖

```
cli.py ──┐
gui/   ──┴─→ engine/pipeline.py（编排层，唯一业务判断入口）
                │
                ├─→ rules/（formulas + params 门控）
                ├─→ io/（解析）
                ├─→ alert/
                └─→ report/
```

**硬纪律**：
- **编排上收**：CLI 与 GUI 共用 `engine/pipeline.py` 的公开函数组，前端只渲染、零判定逻辑——**同一业务判断在项目里只能有一处实现**；
- **GUI 分层靠 AST 静态门禁守住**（三条齐上）：① 不 import 规则层/引擎内部模块；② 无 `BinOp` 算术（`*` `/` `-` `//` `%` `**`，两侧操作数均非字符串字面量）；③ 无禁用数值字面量。**只守 import 面会漏掉"界面里直接算/内联数值"**；
- **惰性导入**：重件（PySide6）只在函数体内 import；`try/except ImportError` 必须包住**从 import 到调用完成的整条路径**（不是只包 import 行——分层越严，这个边界越靠后越易漏）；
- **单件与批量共用同一分派点**（`check` 与 `batch` 走同一个解析/判定函数，别复制粘贴判定逻辑）。

## 四、口径单一定义点（防"第二份真相"）

| 事实 | 唯一定义点 | 引用方 |
|---|---|---|
| 换算公式 F1–F6 | `rules/formulas.py` | 引擎 / 报告 / 基准 / plan/02 |
| 参数默认值与 status | `data/rules/params-*.json`（生成器产出） | 引擎（经 `effective_params` 门控）/ 报告参数来源块 |
| 报告章节结构 | `report/sections.py` | Markdown 渲染器 + XLSX 渲染器（→ 内容一致是结构性质） |
| 真值对账语义 | `benchmark/cases.py` | 真值库测试 + 基准（→ 无双口径漂移） |
| 真值库内容（输入 + 期望键） | `data/truth/*.json`（由 `tools/gen_truth.py` 产出，**禁手改**） | 基准活体观测对账 + 真值库守门测试 |
| 验收门槛与覆盖度登记 | `data/truth/manifest.json`（同一生成器产出，**数据非代码**） | `benchmark/runner.py` 只读（缺失即 `ConfigError` exit 2，不回落默认值） |
| 打包数据白名单 | `rcc/packaging.py` | spec / 构建后断言 / 白名单守门测试 |
| **随包数据定位**（源码态与冻结态同一答案） | `rcc/packaging.find_data_dir()` | `rules/params.py` / `benchmark/runner.py` / `benchmark/cases.py` / `selftest.py`（**M5 收敛**：原 runner 与 cases 各按 `__file__` 上溯，冻结态落空） |
| 快照台账（数据日/抓取日/URL/sha256/品类覆盖） | `data/snapshots/ledger.json` + `README.md`（由 `tools/fetch_snapshots.py` **同源渲染**） | 抓取器 `--check` / 快照守门测试 / 报告参数来源块 |

**零字面量门禁**（`tools/check_literals.py`）扫描面随交付形态扩张：**整包 `src/rcc` + `benchmark/`**，含 docstring 与注释。新增源码文件前先问：**"这个文件里会出现任何禁用数值形态的字符串吗？"**
（**M3 收紧**：原先逐目录枚举 `engine/` `alert/` `rules/` `cli.py` `report/` `gui/` `benchmark/`，漏掉了同属计算路径的 `selftest.py`——它带着手写的公式探针数值待在面外。枚举式扫描面的失效模式是"漏一个文件而不自知"，故改整包。）

**公式原文的单一来源**（M3 落地）：plan/02 §一 表格的每条公式原文，被 `rules/formulas.py` 对应函数的 docstring **逐字复述**，由 `tests/guards/test_formula_single_source.py` 断言两处一致。于是"公式与注记同源一致"是可证伪的性质——**同一算式在扫描面内只准有一处实现**（例外：`benchmark/runner.py` 按 B5 设计独立重算，属"两条独立路径互验"）。

```
                                  ↓

```

## 六、决策记录（M0 期）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **LLM 使用：不使用** | 本领域为纯确定性规则 + 结构化输入，无"非结构化解析兜底"需求 → 全链路零 LLM：结论 100% 可复现、零 API 依赖、基准离线可跑、脱敏面无外部调用。显式登记免被误读为遗漏 |
| 2026-10-15 | 仓库可见性：**public**（用户明确要求"上传 GitHub"） | 用户对话中的明确表态优先于计划文档旧结论；M6 执行"先清后切"三清门（先全历史脱敏 + 坏 blob 修净 + 失败 run 删，再转公开） |
| 2026-10-15 | 核心零第三方依赖（引擎/解析/基准） | 可复现性优先；报告 XLSX 自写最小 writer 保字节确定 |
| 2026-10-15 | 提交邮箱必须全历史改写 | M0 实测本机 `git config user.email` 为**真实个人邮箱**（非占位），发布前用 `git filter-repo` 改写为 GitHub noreply |
| 2026-10-15 | CI 于 M0 即配（不推迟到发布期） | 避免"把全项目 CI 首跑风险压进发布窗口"的反模式；M0 配齐 EOL 门 + 编码三层加固 + extras 含测试期依赖 |
| 2026-10-15 | 数据底座复核：新发地 API **可用且支持历史日期查询** | M0 实测 `pubDateStartTime`/`pubDateEndTime` 可取指定日快照（2026-08-06 / 09-06 / 10-06 大白菜 0.55/0.53/0.40 元/斤，与题面一致）；`prodName` 与 `prodPcatid` 组合过滤有效（仅 prodName 单独过滤无效）；品类 id 实测 1186 蔬菜 / 1187 水果 / 1189 肉禽蛋 / 1190 水产 |
| 2026-10-15 | 快照**整日全品类**留档（非按品类拆文件） | M1 实测整日查询与四品类求和的 `id` 集合逐条相等；整日一份件即完整留档，逐品类查询改作**抓取期交叉核验**（断言并集 == 整日记录数）。理由 = 少文件、少一次 sha256 登记面，且"整日完整性"是可直接断言的性质 |
| 2026-10-15 | 快照期间标识用 `data_date`，`captured_date` 另存 | M1 实测：两期不同数据日若都用抓取日标识，输出里**不可区分**（"两期退化成同一期"的第二形态）。`date` ← `data_date` 作期间标识，`captured_date` 保留供留档可复现；`compute_alert` 对数据日相同显式拒绝（exit 2） |
| 2026-10-15 | **进货单首期只支持 CSV，Excel 列扩展项** | 定夺 HANDOFF-M2 记的口径冲突（README"仅 CSV" vs plan/00·01"CSV/Excel"）。理由：M2 DoD 不涉 Excel；"核心零第三方依赖"下 Excel 必破约束（`openpyxl`）或引入 `zipfile`+XML 读路径并纳入 EOL/外链/确定性守门面。**用户明确选择此口径** |
| 2026-10-15 | **`io/csv_import.py` 是 `check` 与 `run` 的唯一分派点** | plan/06 早已写"单件与批量共用同一分派点"但无守门。M2 补三道门（`tests/guards/test_import_dispatch.py`）：① AST 断言 `pipeline` 内**无第二份列名映射**；② **行为计数探针**断言两条通路真调用同一解析函数（源码字符串匹配证明不了调用）；③ 同一输入下两条通路的异常清单**逐条等同** |
| 2026-10-15 | **进货单非 UTF-8 一律拒绝，不猜测编码** | 贪心/试探式解码会把 GBK 字节静默解成乱码品名，产出"自洽但错"的食材库——比报错危险得多。报错文案点明"请另存为 UTF-8" |

### 决策记录（M3 期）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **零字面量扫描面改为整包扫描** | 逐目录枚举会漏文件（M3 实测：`selftest.py` 漏在面外且带着手写的公式探针数值）。**枚举式扫描面的失效模式是"漏一个文件而不自知"**，整包扫描使计算路径上任何源码无处可逃；同步收紧词边界防版本号误报 |
| 2026-10-15 | **公式原文锚定进 `formulas.py` docstring + 新守门 G-FORMULA-SRC** | 让"口径单一定义点"从人工比对变成可断言性质。门当场抓出 `alert/threshold.py` 的第二份 F5 实现（`delta / old_cost`），已改为调用 `formulas.change_rate`。**"文档说一套代码做一套"不会自己暴露，必须靠门** |
| 2026-10-15 | **`input_required` 与 `pending` 语义分开落地** | 原实现把两者同形（整域抛错），与 plan/02 §三"放行门控"的声明矛盾。修正为：门控放行、值不进可用集、索取发生在取数点。**"放行"不等于"静默取默认值"** |
| 2026-10-15 | **`yield_rate` 越界 → 行级 invalid（不中断整批）** | plan/02 §一 早已写"越界一律判该行 invalid 并列入清单"，实现却是整单抛错。修正后行级问题 exit 1、全排除则文件级 `no_usable_dishes` exit 2。**行级代码与文件级代码不混用**（同 K28） |
| 2026-10-15 | **`SourceMissing` 继承 `ValueError`** | 裸 `Exception` 不被 CLI 的 `except (ParamsError, ValueError)` 捕获 → 逃逸成未捕获 traceback。它是一条明示的失败路径（exit 2），必须被捕获 |
| 2026-10-15 | **来源校验移到消费点 + `qty` 补挂来源** | 构造期校验只守"自己造的那一半"；来自解析后外部文件的来源对象不经过它。`qty` 由 plan/02 §二 早已列入参数表，实现却没挂——已补（文件级 `kind = user`） |

### 决策记录（M4 期）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **真值库只存输入与期望；观测是活的观测器实算** | 原 `_sample_suite` 比对的是真值库**内部**两个冻结字典（`expect` vs `observed`），**从不跑引擎**——"基准全绿"可能只是"基准什么都没查"。M4 把观测移出真值库：`benchmark/cases.py::observe_*` 把用例的内联输入**真喂引擎**后实算结论键。**判据：真值库里出现 `observed` 即红**（G-TRUTH-FROZEN） |
| 2026-10-15 | **对账单元升级为"自带结论的键"** | 集合对账配"状态当值"看不见差异（`up`/`down` 字段名集合相同）→ 误分类静默通过。改为 `status:X=down` 一类键名，**值的变化即改变键名**。对账语义仍单一实现源（`benchmark/cases.py` 的 `confirmed_keys`/`compare_nonpass`），真值库测试与基准共用 |
| 2026-10-15 | **覆盖度分母从代码常量集反射；分子必须等于分母** | "只写分子即假覆盖"还差一步"分母从哪来"。M4 定为：`csv_import`/`pipeline` 的 `ISSUE_*` **运行时反射** + 登记的结构性形态；**新增代码而无用例 → 生成器直接报错**（`TRUTH_FORMS_INCOMPLETE`）。"分母被悄悄做小"这条路被堵死 |
| 2026-10-15 | **门槛字段全部参与判定；不可测的显式声明未测** | `max_duration_seconds` 原先登记了却没人看（"登记了却静默不判"）。现真判时长。误报率在样本层**实测**（观测多出的键占比），规则驱动层结构上不可测 → manifest 用 `measures_false_positive` **显式声明**，不拿恒 0 冒充达标 |
| 2026-10-15 | **新增 `tools/gen_truth.py`，与其他生成器同构** | `--check` 位级一致（`FROZEN_TRUTH_OK`）、确定性纪律（禁 stdlib random / set 序 / 时钟、`newline="\n"`）、入口守卫 `ensure_utf8_stdio()`，并由既有 G-ENCODING 门自动覆盖新脚本 |

### 决策记录（M5 期）

| 日期 | 决策 | 结论与理由 |
|---|---|---|
| 2026-10-15 | **打包入口独立成 `tools/launcher_*.py`，不拿包内 `cli.py` 当入口** | PyInstaller 把入口脚本当**顶层模块**执行，包内相对导入（`from . import __version__`）当场 ImportError。启动器只装编码守卫 + 转交 `rcc.cli:main`，**零业务判断**——判定逻辑若在启动器里长一份，就是第二处口径 |
| 2026-10-15 | **`build_datas()`：目录条目取条目自身作目标目录** | 实装 spec 时抓到真实缺陷：三个目录条目全用 `dirname(rel)` 作 dest，而 PyInstaller 把目录源**内容**复制进目标目录 → 随包快照/样例/真值库被拍平进 `data/`，冻结态按 `data/snapshots/` 取数落空。**构建不报错，源码态全绿，只有换机器才炸**。故 G-PACK 的核心断言语义从"spec 里没写某字符串"升级为"包内路径 == 仓库内相对路径" |
| 2026-10-15 | **冻结态数据定位收敛到 `find_data_dir()` 单一入口** | `benchmark/runner.py::TRUTH_DIR` 与 `cases.snapshot_path()` 原各按 `__file__` 上溯拼路径，冻结态指向不存在的"仓库根"。收敛后：runner 用 `find_data_dir()/truth`、cases 用 `dirname(find_data_dir())/data/snapshots/…`。**"数据在哪"与"数据怎么装进去"是同一口径的两面**（同 K13 的单一来源纪律） |
| 2026-10-15 | **GUI 分层门禁分两面：AST（恒跑）+ 行为（也不依赖重件，恒跑）** | `tests/guards/test_gates.py` 的 AST 三条守**形状**；`tests/gui/test_layering_behavior.py` 守**行为**——`import rcc.gui` 不得把 PySide6 拉进 `sys.modules`（`cmd_gui` 的 `try/except ImportError` 能包住"从 import 到调用完成"的前提正是它）。只有真需要 Qt 的窗口冒烟才 `importorskip`。**别把分层门禁搬进可 skip 的目录**——那会让"没装 gui extra 的机器上界面分层无人守" |

## 七、边界与非目标（复核题面 §6）
