# plan/03 基准套件设计

仓库 `10-15-recipe-cost-calculator`。v2（2026-10-15，M4 实现后回写实测数值）。M0 定稿（设计期），M4 实现并回填实测数值。

## 一、基准的双层结构（样本驱动 + 规则驱动）

只做样本驱动会漏掉"样本没覆盖的端点"——所以两层都要有（skill 阶段 5）。

| 层 | 套件 | 输入来源 | 证明什么 | 不依赖真值库 |
|---|---|---|---|---|
| 样本驱动 | `import`（B1） | 生成器产样例进货单 + 真值 | 解析层在这些样本上对 | 否（用真值库） |
| 样本驱动 | `costcard`（B2） | 生成器产 BOM + 参数包 + 真值 | 成本卡端到端在这些样本上对 | 否 |
| 样本驱动 | `alert`（B3） | 两期快照 + 真值 | 预警清单与排序在这些样本上对 | 否 |
| **规则驱动** | `boundary`（B4） | **只读参数包与公式定义，不读真值库** | 引擎在**所有**有限端点上对 | **是** |
| **双向对账** | `reconcile`（B5） | 公式推导端点 vs 穷举扫描恢复切换点 | 两条独立实现路径互验 | 是 |

**B4/B5 是"规则驱动"层的关键**：B2 的真值库只覆盖采样的净料率/用量，它证明不了"净料率=1.0 边界""用量=0""目标毛利率→1"这些端点的行为；B4 从参数包本身推导全部有限边界做 ±精度邻域断言。

## 二、真值库形态与语义

- **文件**：`data/truth/<suite>.json`，由 `tools/gen_truth.py` 程序化产出，**禁手改**；配 `--check` 位级一致守门（`FROZEN_TRUTH_OK`）。
- **记录语义**（定一次，写进 `tools/gen_truth.py` 模块注释）：
  - `input` = 用例的**内联输入**（CSV 文本 / BOM JSON / 快照相对路径 / 参数覆盖）；
  - `expect_keys` = **冻结期望结论键**（对账单元）；
  - **不含观测结果**——观测由 `benchmark/cases.py` 的观测器在**运行时**实算。
- **观测必须是活的（M4 关键）**：若把观测也冻进真值库，评测就退化成"比对两个冻结字典"——**引擎坏掉也照样全绿**，那正是本项目最忌的假门。故真值库只存输入与期望，观测一律实算；守门 `tests/guards/test_truth_frozen.py::test_truth_libraries_hold_no_frozen_observations` 断言真值库里没有 `observed` 一类字段。
- **结论键自带结论**：键形如 `status:大白菜=up`、`cost:醋溜白菜=3.24`、`issue:L3:not_numeric:invalid`，取值恒为 `ok`。对账仍落在"字段集合"上（对账语义**收成单一实现源** `benchmark/cases.py` 的 `confirmed_keys` / `compare_nonpass`，真值库测试与基准**共用同一函数**），但**值的变化会改变键名**——只把状态当值的话（`{"status:X": "up"}` vs `{"status:X": "down"}`）字段名集合相同，**误分类会静默通过**。
- **禁止改真值凑引擎**；但要区分两种修正情形（见 plan/02 §七）：改谓词 vs 引擎与真值同源修正。

## 三、确定性生成纪律（真值与样例）

- **禁 stdlib `random`**：自研 splitmix64 确定性 RNG（`tools/detrng.py`），固定 seed 可复现；stdlib `random` 不承诺跨版本序列一致。
- **禁 `set` 迭代序、禁系统时钟**：落盘产物**无时间戳**，两次运行逐字节一致（配守门测试）。
- **文本落盘 `newline="\n"` / `write_bytes`**，防 Windows 把 `\n` 翻成 `\r\n` 触发 EOL 门。
- 生成器必须提供 `--check`：重算并与入库件逐字节比对，不一致即 exit 1。
- 生成的样例目录整体作为**字节冻结 fixtures 入仓**（禁止手改；改体例 → 用固定 seed 命令重新生成整目录并提交）。

## 四、覆盖度口径（**总数/采样数双登记**，防假覆盖）

覆盖声明必须同时写出**分母（总数）与分子（采样数）**——只写分子就是假覆盖（skill 阶段 5）。M4 已实测回填下表，并在 `data/truth/manifest.json` 逐形态登记。

| 套件 | 形态维度 | 形态总数（来自参数包/代码） | 真值采样数 | 采样清单 | 声明 |
|---|---|---|---|---|---|
| B1 import | 正常行 / 数值越界 / 非数值 / 缺列 / 未登记列名 / 单位不一致 / 形态失败 5 类 / BOM 表头 / 列序任意 / 表头空白 / 空行 / 金额不校验 / 重复品名 | **18** | **18** | `manifest.json` → `coverage.import.sampled_forms` | 抽样覆盖，**非穷举** |
| B2 costcard | 单食材 / 多食材 / 多菜 / 净料率=1.0 / 净料率极小 / 用量=0 / 用量为负 / 净料率越界 / 缺条目 / 零可用行 / 全部排除 / BOM 形态失败四条 | **15** | **15** | `coverage.costcard.sampled_forms` | 抽样覆盖，**非穷举** |
| B3 alert | 涨 / 跌 / 平 / 新增 / 消失 / 汇总排序与阈值 / 两期退化守卫 | **7** | **7** | `coverage.alert.sampled_forms` | 抽样覆盖，**非穷举** |
| B4 boundary | 各公式的有限边界（见 §5） | **29** | 29（端点全部） | — | **规则驱动，穷举** |
| B5 reconcile | 互逆往返 + 单调性 + 量化 | **4** | 4 | — | **规则驱动，穷举** |

**分母做不小（M4 机制）**：B1/B2 的形态分母**不由人手写清单决定**——它把 `csv_import` / `pipeline` 的 `ISSUE_*` 常量集**运行时反射**出来，再并上登记过的结构性形态。**新增一个异常代码而没配用例 → 生成器直接报错**（`TRUTH_FORMS_INCOMPLETE`，exit 1），不是"覆盖率悄悄掉一点"。守门 `tests/guards/test_truth_frozen.py` 两条（`test_coverage_denominator_tracks_code_constants` / `..._pipeline_constants`）把这条钉住。
> 判别 = **"这个基准说的 100% 覆盖率，分母是不是被我悄悄做小了？"**——本项目给出的答案是：分母来自代码常量集，做不小；分子必须等于分母，否则生成器拒绝产出。
>
> **形态归属也要算对**：`no_usable_rows` 是**文件级**结论（由 `pipeline` 层发出，`parse_purchases` 从不产出它），故它记在 **B2 分母**（那里有用例覆盖），B1 分母不含它——这不是"做小分母"，是把形态算在正确的层上（同 K28：行级代码与文件级代码不混用）。

**"未启用"套件不冒充通过**：某套件的分母为 0 时，结果必须 `not_enabled=true` + `notes` 写明"该类用例未生成" + **exit 1**（不是 exit 0）；`--only` 部分运行时不判定未测指标。**每个"达标"分支先问"分母为 0 时它会怎样？"——恒真就是假门。**

## 五、B4 规则驱动的边界清单（从公式推导，代码零字面量）

边界端点**由参数包与公式定义推导**，端点值由参数包逐条算出（不写进代码）：

| 公式 | 有限边界 | ±精度邻域断言 |
|---|---|---|
| F1 净料单价 | `yield_rate = 1.0`（净料单价 = 毛料单价）、`yield_rate → 0⁺`（单价→∞，须有上界守卫）、`purchase_unit_price = 0` | 断言单调性与方向（净料 ≥ 毛料） |
| F2 单份成本 | `qty = 0`（该食材不贡献成本）、BOM 单行/多行 | 断言线性可加性（拆两行 = 一行两倍） |
| F3 建议售价 | `target_margin = 0`（售价 = 成本）、`target_margin → 1⁻`（售价→∞，须拒绝） | 断言单调递增 |
| F4 实际毛利率 | `price = dish_cost`（毛利=0）、`price < dish_cost`（负毛利如实报负，不夹断为 0） | 断言符号与 F3 互逆（F3 反推的价代入 F4 得回目标毛利率，误差 ≤ 量化半步） |
| F5 涨跌幅 | `old_price = 0`（拒绝，非除零）、`new = old`（0%）、涨/跌符号 | 断言符号正确 |
| F6 量化 | 半分位（x.xx5）的 ROUND_HALF_UP 方向 | 断言方向为"远离零" |

**B5 双向对账**：F3 与 F4 的互逆关系用两条独立路径验——① 由公式推导"给定成本与目标毛利率 → 应得售价"；② 在售价区间上**粗扫（1 元步长）+ 恢复窗口逐分细扫**，恢复出使实际毛利率回到目标值的售价。两路径结果一致（差异 ≤ 量化半步）。

**B4/B5 的期望锚定冻结参数包**（不读真值库）——这是它们探活能红的隐含前提：期望与引擎同源时，注入缺陷两边一起变、探活永远绿。

## 六、基准的验收门槛是**数据不是代码**

门槛（达成率下限 / 误报率上限 / 单次运行时长上限）随 `data/truth/manifest.json` 下发；基准层**只读**，缺失即报**配置错误 exit 2**，**不得回落代码里的默认值**（内联门槛 = 抄进代码的第二份真相，且易被误读为业务数值）。

**时长门槛真参与判定**（M4 修）：`max_duration_seconds` 原先**既未校验也未使用**——登记在门槛里却没人看，等于"登记了却静默不判"。现按"实测单套件耗时 ≤ 门槛"判定，超时即该套件未达标（exit 1），输出里给出实测值供读者判断是机器慢还是基准退化了。

**误报率要么实测、要么显式声明未测**（M4 登记）：样本驱动层（B1–B3）的误报率是**实测值**（观测多出的结论键占比）——写死为 0 再与门槛比较是恒真假门（门槛就算配 0 也永远满足）。规则驱动层（B4/B5）没有"观测键"通道，其误报率**结构上不可测**，故由 manifest 的 `measures_false_positive` **显式声明未测**（登记而非沉默），未测即不冒充"误报率达标"。

## 七、每套件配"可证伪"探活（阴性对照）

不配探活时"基准全绿"可能只是"基准什么都没查"。做法：给每套件注入一个缺陷，**断言基准必须报未达标**。

| 套件 | 注入的缺陷 | 期望 | M4 实测落点 |
|---|---|---|---|
| B1 | 篡改一条真值期望（列名改成不存在的） | 基准报未达标（exit 1） | `TestTruthTamperProbes::test_import_tampered_expectation_is_detected` + 变异脚本④ |
| B2 | 破坏 F1 方向（改除为乘） | 基准报未达标 | `TestLiveObservationNotFrozenComparison::test_broken_engine_makes_sample_suites_fail` + 变异脚本① |
| B3 | 篡改排序规则（改降序为升序） | 基准报未达标 | `test_alert_suite_observes_live_sorting` + 篡改分类期望探活 + 变异脚本③ |
| B4 | 篡改公式端点定义 | 基准报未达标 | `TestFalsifiability::test_boundary_probe_catches_broken_direction` / `..._broken_quantize`（后者 M4 补硬：原先只断言坏实现给出不同结果，**没断言套件报未达标**）+ 变异脚本② |
| B5 | 篡改量化方向 | 基准报未达标 | `test_reconcile_probe_catches_broken_roundtrip` |

**探活的隐含前提 = 期望必须有独立来源**：期望值与引擎**同源**时，注入缺陷两边一起变、探活永远绿。所以 B4/B5 的期望锚定**参数包**（冻结产物）而非引擎代码；B1–B3 锚定**冻结真值库**（且真值库里**不含观测**——含了就两边一起变）。

**M4 实测**：八条变异（F1 方向 / 量化方向 / 排序方向 / 篡改真值期望 / 新增 `ISSUE_*` 代码而无用例 / 删真值库 / 把观测冻进真值库 / 时长门槛登记了却不判定）**全部被检出**（`MUTATION_ALL_RED`，脚本在仓库树外副本上做，工作树无残留）。

## 八、退出码三语义（锁进测试）

| 码 | 含义 |
|---|---|
| 0 | 全部达标 |
| 1 | 未达标 **或** 计算非法 **或** 套件 `not_enabled` |
| 2 | 用法错误 / 坐标错误 / **`--only` 传未知名** / 门槛配置缺失 |

`--only` 传未知名必须走 exit 2——否则"跑了个不存在的基准"会被读成成功。**新增基准要注册进 `--only` 白名单**，未知名 → exit 2，不静默跳过。

## 九、覆盖度的"如实声明"（不假装覆盖没有的规则类型）

若某类用例**在设计上就没生成**（如首期不参数化某维度），对应套件的 `notes` 要**如实写"该类用例未生成"**，**不假装覆盖**，也不为凑覆盖率造假规则/假用例。设计成"若将来建了该类规则，基准自动开始覆盖"（由 `missing_check_types` 类机制驱动）。

判别 = **"这个基准说的 100% 覆盖率，分母是不是被我悄悄做小了？"**

## 十一、共同验收门（M4 统一）

**修正纪律**（plan/02 §七）：改口径前先判是"**校验方式不自洽**"（只改谓词）还是"**口径本身定错**"（引擎与真值同源修正，两边一起改）。

**共同验收门** = `tools/gen_params.py --check` + `tools/gen_samples.py --check` + `tools/gen_truth.py --check` 三者都输出 `OK`。
> **命名统一（M4 定夺）**：plan/02 §七 写 `gen_truth.py --check` 输出 `FROZEN_TRUTH_OK`，与现有生成器（`gen_params`/`gen_samples`）各自的 `FROZEN_*_OK` 命名一致——M4 实现按 **plan/02（口径来源）** 落到 `FROZEN_TRUTH_OK`。
