# plan/04 测试与验收

仓库 `10-15-recipe-cost-calculator`。v1（2026-10-15）。M0 定稿（设计期），各里程碑实现后回填实测结果。

## 一、测试分层

| 层 | 位置 | 覆盖 | 依赖 |
|---|---|---|---|
| 单元测试 | `tests/unit/` | 公式、参数门控、解析器（**三态矩阵**：每格一个用例）、报告章节函数 | 无（纯 stdlib + 本包） |
| 守门测试 | `tests/guards/` | EOL/CR 门、零字面量门禁自检、冻结产物位级一致、packaging 白名单、README 引用可跑通、编码守卫覆盖、AST 分层门禁、**导入分派点门** | 无 |
| 集成测试 | `tests/integration/` | CLI 端到端 + 退出码三语义 | 无 |
| 基准测试 | `tests/benchmark/` | 五套件 runner + 探活（阴性对照） | 无（离线可跑） |
| GUI 测试 | `tests/gui/` | offscreen 冒烟 + 分层门禁 | PySide6（模块级 `importorskip`） |

**核心纪律：测试全离线**，零 API 依赖、零网络。基准可离线复跑。

## 二、退出码语义（锁进 CLI 测试，重构不漂移）

| 码 | CLI `run` | CLI `check`（校验） | 基准 |
|---|---|---|---|
| 0 | 完成 | 全部合规 | 达标 |
| 1 | 降级完成（有异常行/未启用套件） | 检出问题 | 未达标 / `not_enabled` |
| 2 | 输入不可用（文件缺失/格式坏/参数错误） | 同上 | 用法或未知名错误 |

**批量通路的退出码纪律**（skill 阶段 6）：① **失败件 ≠ 违规**——坏 JSON/不可解析记 `parse_error`，**不改变退出码**（退出码由"是否检出问题"决定）；② **失败隔离**——单件异常不中断整批，失败件单列，绝不静默吞掉。

## 三、必测的失败路径

**形态失败（整份文件不可用 → exit 2，不进逐行清单）**：

- 缺文件 / 坏格式 / 空文件 / 仅空白 / **只有表头无数据行**；
- **非 UTF-8 编码**（不做编码猜测，显式拒绝）；
- **缺必填列**（表头不完整，报错须点名缺哪列）；
- **CSV 结构错**（字段内 NUL 等，`csv.Error`）。

**行级失败（exit 1，逐条进异常清单）**：

- 进货单数值越界、非数值、必填列为空、未登记列名（`mapping_uncertain` 第三态）、
  **整行结构不可解析**（字段数多于表头 → `unknown` 且该行不入库）、**单位未登记**；
- **全行异常**（零可用行）→ 报错必须指向进货单，**不得**由下游报"BOM 引用了不存在的食材"。

**其余**：

- 参数包条目 `pending` → 门控拦截，exit 1，**打印"未启用清单"**；**三个 scope 各要有一例**（只测一个等于没测其余两个）；
- 参数包条目 `input_required` → **放行门控**（不阻断该作用域），但其值**不进可用集**；运行时由取数点索取，缺失 exit 2（**不静默取默认值**）；
- `source` 缺失 → `source_missing` 拒绝（`SourceMissing` 继承 `ValueError`，**exit 2 而非未捕获 traceback**）；**每个 scope 都要有一例**；
- **来源校验在消费点**（不只构造期）：来自解析后外部文件的来源对象必须被校验；`qty`（BOM 用量）必须挂来源；
- `target_margin = 1.0` → 拒绝（非除零），exit 2；
- `old_price = 0` → 拒绝（非除零），exit 2；测试须选**被 BOM 引用**的食材置零，否则 F5 不被触发（**恒真假门**）；
- **`yield_rate` 越界 ∉ (0,1]** → 该行（该菜）`invalid` 并入清单，**整批不中断**（exit 1）；**全部菜品都被排除** → 成本卡为空 → `no_usable_dishes`（line=0）→ exit 2；**不得静默取 0/1**；
- **BOM 形态失败四条**：缺 `dishes` 数组 / 空数组 / 菜品缺 `name` / 引用不存在的食材 → 一律 exit 2；
- GUI 缺 PySide6 → exit 3（**惰性导入 try 包住从 import 到调用完成的整条路径**，不是只包 import 行）；
- 报告未启用预警时章节显式写出"本次未启用"。

## 四、守门测试清单（每条都要能**证伪一次**）

| 守门 | 断言 | 变异验证（故意弄坏 → 门必须变红） |
|---|---|---|
| G-EOL | 全部跟踪文本文件无 `\r` | 往一个 fixtures 文件写 CR → 必须 FAIL |
| G-FROZEN | 生成器 `--check` 位级一致 | 手改一个冻结 JSON → 必须 FAIL |
| G-LITERAL | 零字面量门禁 + `--selftest` 阳性/阴性对照 | 在引擎源码里写一个禁用数值 → 必须 FAIL |
| G-AST-LAYER | GUI 层不 import 规则层、无 `BinOp` 算术、无禁用数值字面量（**三条齐上**） | 在 GUI 里写 `a * 1.5` → 必须 FAIL |
| G-README | 正则抽取 README 代码块里的输入参数，断言路径存在 + 按退出码表真跑 | 把 README 里一个输入路径改成不存在的 → 必须 FAIL |
| G-ENCODING | AST/正则断言每个可执行入口（CLI + `tools/*.py`）都有 `_ensure_utf8_stdio` 调用 | 删掉一个脚本的入口守卫 → 必须 FAIL |
| G-CI | 解析 workflow，断言每个 checkout 的 `fetch-depth == 0`、每个 job 有 `runs-on`/`steps`、YAML 可解析 | 删掉 `fetch-depth: 0` → 必须 FAIL |
| G-PACK | spec 无手写数据路径、无禁区字面；datas 只由 `build_datas()` 产生 | 在 spec 里手写一个路径 → 必须 FAIL |
| G-REPORT | 同输入两次导出报告字节一致；无外链；溯源行数对账 | 让 XLSX writer 用当前时间 → 必须 FAIL |
| G-AUDIT | 脱敏扫描器四模式 + selftest 阳性/阴性对照 | 在仓库放一个假手机号 → 必须 FAIL |
| G-SNAPSHOT | 快照 sha256 与台账登记值一致（**实算**而非抄读）；台账/README 与磁盘实况同源；≥3 个**可区分**数据日；原始件无 CR；`-text` 已标 | 篡改一份快照副本一个字节 → 必须 FAIL |
| G-SNAPSHOT-SELFTEST | 抓取器 `--selftest` 阳性/阴性对照（篡改原始件 / 篡改台账 sha256 / 手改 README 三种注入） | 使校验器恒返回空漂移 → 必须 FAIL |
| G-DEGENERATE | 同一份快照当两期 → 必须 exit 2（**不产出"全平"假结果**）；两期数据日必须在结果里可区分 | 去掉数据日相等判定 → 必须 FAIL |
| **G-IMPORT-DISPATCH** | ①AST：`engine/pipeline.py` 内**无第二份列名映射**；②**行为计数探针**：`check` 与 `run` 两条通路都真调用 `csv_import.parse_purchases`；③同一输入下两条通路的异常清单**逐条等同** | 在 `pipeline` 里另写一份列名映射或另写判定分支 → 必须 FAIL |
| **G-FORMULA-SRC**（M3 新增） | ①plan/02 §一 的每条公式原文必须**逐字**出现在 `formulas.py` 对应函数的 docstring 里；②F1 方向注记与取值域 `(0, 1]` 两侧都在；③**扫描面内除法 BinOp 只准出现在 `formulas.py` 与 `benchmark/runner.py`**（后者是 B5 设计所需的独立路径），其余位置出现即"第二份公式实现" | 去掉任一 docstring 的公式原文 / 在别处手写同一算式（如 `alert` 里写 `delta / old_cost`）→ 必须 FAIL |
| **G-LITERAL-FACE**（M3 收紧，并入 G-LITERAL） | 扫描面为**整包** `src/rcc` + `benchmark`（非逐目录枚举）；词边界尾端排除 `\.[0-9]`（版本号不误报）；`--selftest` 含版本号形态对照 | 把扫描面退回逐目录枚举（漏 `selftest.py`）/ 词边界退回旧形态（版本号刷屏）→ 必须 FAIL |

**变异验证是硬要求**：`assert "xxx" in source` 这类字面断言证明不了函数被调用。每条守门必须实测"弄坏被测行为 → 门变红"一次，结论留档。

## 五、测试面 = 安装面（干净环境验证的判据）

**测试套件真 import 的每个库，都必须在 README 快速开始那条安装命令的 extras 里找到**。

- README 快速开始与 CI 全部"跑测试"的 job 用**同一 extras 集合**（如 `.[dev]`）；
- GUI 交互测试用 `importorskip` 声明式跳过属合法形态（AST 门禁类测试不依赖重件照跑）；
- 但**"产物存在性断言"类测试**的依赖必须进安装面——否则干净 venv 里**硬失败**（不是 skip）；
- **核心层能力不许整体 skip**：若一条用例同时验"需 extra 的格式导出"和"零依赖的核心通路"，按环境**裁剪断言范围**（核心部分恒跑），不整条 skip。

## 六、干净环境验证（发布门，M6 执行）

1. `git archive HEAD | tar -x -C <树外新目录>` 导出跟踪树（天然无 `_private/`、无 `.git`）；
2. 全新 `py -3.12 -m venv`（本机 `python` 是商店占位符时用 `py -3.12`，语义逐字、创建工具换本机可用通道）；
3. **逐条照 README 快速开始执行**，逐条记录退出码成表；判据是"符合 README 明示的退出码语义"，**退出码非 0 ≠ 跑挂**；
4. pytest **收集数对账**：**同一 extras 集合下** dev 与干净环境必须一致（收集数**随 extras 变**——模块级 skip 会把整模块用例移出收集面）；
5. 计数差异**逐项归因**到声明式跳过，写进发布留档（"全绿"不可直接比 passed 数）。

## 七、编码守卫三层加固（CI 首跑最常见的红）

判别线索：**windows 全挂 + ubuntu 全过** → 先假定"编码/代码页"，同时排查三层：

| 层 | 措施 | 救谁 |
|---|---|---|
| CI 全局 | `env: PYTHONUTF8: "1"` + `PYTHONIOENCODING: "utf-8"` | CI 全部步骤（**只救 CI，不能当唯一手段**） |
| 代码入口 | `_ensure_utf8_stdio()`（按 `stream.encoding` 探针决定是否 `reconfigure`，中文控制台 cp936 保持不动） | 真实用户 |
| 子进程解码 | `subprocess.run(..., encoding="utf-8", errors="replace")` | 一切环境（**无环境变量可替代**，必须逐调用点写） |

**入口守卫必须覆盖所有会打印的可执行入口**，含 `tools/` 下每个脚本**与里程碑后期新增的脚本**——不是只守主命令。配 G-ENCODING 守门。
