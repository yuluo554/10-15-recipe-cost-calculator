# plan/02 算法与口径说明

仓库 `10-15-recipe-cost-calculator`。v1（2026-10-15）。**本文件是全部数值口径的单一定义点**：引擎实现、注记、报告、文档一律引用此处，禁止任何地方手写第二份口径（含 docstring 与注释里的示例数值）。

> 状态：M0 定稿（口径设计期）。**M3 实现时若实测发现口径不自洽，按"引擎与真值同源修正"处置并回写本文件 + 决策记录**（见 §7）。

## 一、换算公式（六条，F1–F6）

定义域与前提校验写在同一处（`src/rcc/rules/formulas.py`），越界一律判该行 `invalid` 并列入异常清单，**不静默跳过、不静默取 0/1**。

| 编号 | 名称 | 公式 | 前提校验 |
|---|---|---|---|
| F1 | 净料单价 | `net_unit_price = purchase_unit_price / yield_rate` | `yield_rate ∈ (0, 1]`；`purchase_unit_price ≥ 0` |
| F2 | 单份成本 | `dish_cost = Σ_i (net_unit_price_i × qty_i)` | `qty_i ≥ 0`；BOM 非空 |
| F3 | 建议售价 | `suggested_price = dish_cost / (1 - target_margin)` | `target_margin ∈ [0, 1)`（=1 不可解，门控拒绝） |
| F4 | 实际毛利率 | `actual_margin = (price - dish_cost) / price` | `price > 0` |
| F5 | 涨跌幅 | `change_rate = (new_price - old_price) / old_price` | `old_price > 0` |
| F6 | 量化（呈现口径） | 金额/单价 → `quantize(0.01, ROUND_HALF_UP)`；比率呈现 → `quantize(0.0001)`（即百分比两位小数） | — |

**语义注记（易错点，实现与真值都必须遵守）**：

1. **F1 的毛料/净料方向**：`purchase_unit_price` 是**毛料**进货单价，`yield_rate = 净料重 / 毛料重 ≤ 1`，因此净料单价**必然 ≥ 毛料单价**。任何实现若算出净料单价 < 毛料单价即为方向反了。
2. **损耗率不是第二个参数**：`loss_rate = 1 - yield_rate` 是**同一参数的换算面**。参数包**只存 `yield_rate`**，损耗率仅在呈现层由它导出——避免"同一事实两份真相"（改了净料率忘了改损耗率）。
3. **量化只作用于对外输出，不作用于中间量**：`dish_cost` 与 `net_unit_price` 全程 Decimal 全精度；只有**对外呈现**（报告单元格、CLI 打印）才 quantize。唯一例外是 F3：**建议售价是对外挂牌价，必须先 quantize 再据此算 F4 实际毛利率**（真实挂牌价是分位值），此例外显式声明于此。
4. **Decimal 全链路**：JSON 加载一律 `parse_float=Decimal`，金额/单价/比率字段禁止 float。理由：F4/F5 要检出 1 分/1 个基点的差异，float 尾差不可接受。
5. **不做的事**：不做"定价建议"（不给"应该涨价"这类模糊输出）；不做营养成分；不做进销存流水。预警只输出提示清单（F5 超阈值），**不自动改价**。

## 二、参数体系与来源标记

每个进入计算路径的参数**必须挂 `source` 对象**；缺失或 `kind` 为未登记值的条目，引擎入口门控直接拒绝（`source_missing`）。

| 参数 | 承载位置 | `source.kind` | 默认值出处 | 能否被用户覆盖 |
|---|---|---|---|---|
| `purchase_unit_price` | 进货单/快照 | `snapshot` | 新发地公开批发价快照（含抓取日期） | 是（用户自填进货单） |
| `yield_rate` | 参数包 | `builtin_experience` | 规则包内置经验值 | 是（用户配置优先） |
| `target_margin` | 参数包（示例值） | `user` | 规则包示例值 | 是 |
| `alert_threshold` | 参数包（示例值） | `user` | 规则包示例值 | 是 |
| `qty`（单份用量） | 菜品 BOM | `user` | 用户配方 | 是 |

`source` 结构：`{"kind": "...", "ref": "<文件/来源标识>", "date": "YYYY-MM-DD"|null, "note": "..."}`。

**红线（题面既定）**：`yield_rate` / `alert_threshold` / `target_margin` 的内置值**均为经验值或示例值，非官方数据**。参数包与报告必须逐处带"非官方出处"声明；**禁止在任何用户可见位置把这些默认值表述为官方/标准值**（无权威公开官方损耗率表，见 data/README.md #8）。

## 三、参数包（`data/rules/params-*.json`）——冻结产物

- **形态**：生成器 `tools/gen_rulesets.py` 产出，**禁手改**；改需求走"生成器整目录重生成"，配"再生成逐字节一致"守门测试（`--check`）。
- **落盘确定性**：`ZIP_STORED` 无关（非 zip），但**禁 stdlib `random`、禁 `set` 迭代序、禁系统时钟**；JSON 用固定 `sort_keys=True` + 固定缩进 + `newline="\n"` 写盘，两次运行逐字节一致。
- **条目 status 三态**（只有 `cost`/`pricing`/`alert` 三个 scope 各自校验自己引用的条目）：

| status | 含义 | 门控行为 |
|---|---|---|
| `verified` | 值已核对（对 `snapshot` 类=快照已落盘且 sha256 登记；对经验值=已在参数包内显式登记"经验值"定性） | 放行 |
| `pending` | 待核对 | **阻断该 scope 的判定路径** |
| `input_required` | **本不由参数包承载**的外部输入（如某食材用户未提供净料率） | **放行门控**，但运行时显式索取；缺失即 exit 2，**绝不静默取默认值** |

> 判别口诀（skill 阶段 1）：**"未核对"与"本不由参数包承载"是两回事**——前者挂 `pending` 拦门，后者挂 `input_required` 放行但运行时必索。

- **门控按计算路径分作用域**（skill 阶段 1 GHG 条）：`effective_params(scope)` 三作用域 `cost` / `pricing` / `alert`。**不用"整包全 verified"当唯一门**——否则与核算无关的 `pending` 会阻断整个核算路径，使 M3 的"出数"不可达。

## 四、零字面量门禁（`tools/check_literals.py`）

- **禁用 token 全部运行时实算**：从 `data/rules/params-*.json` 读出全部数值（原样字符串形式 + 对应小数形式），源码与留档**零词面**（扫描器自身不内嵌任何数值）。
- **扫描面**：`src/rcc/engine/`、`src/rcc/alert/`、`src/rcc/rules/`、`src/rcc/cli.py`、`src/rcc/report/`、`src/rcc/gui/`、`benchmark/`——**含 docstring 与注释**。每次新增交付形态，先问"它该不该进扫描面？"（skill 阶段 6）。
- **豁免口径（写死，否则门禁刷屏）**：
  - 精度/基数约定：`0`、`1`、`2`、`100`、`0.01`、`0.0001`（量化与百分比基数，属精度约定而非政策数值）；
  - 数值必须带**词边界**匹配，防 `0.8` 命中 `0.85` 的子串。
- **`--selftest` 阳性对照**：程序化合成一个含禁用 token 的假源码字符串，断言扫描器报红；阴性对照断言干净字符串不报红。**无自检的门禁可能一直是空扫**（skill 阶段 5）。
- **门禁对"非计算代码"同样生效**：CLI 帮助文本、GUI placeholder、报告模板里的示例数值都算——占位一律用中性文本（如 `<净料率>`），不写示例数字。

## 五、判定语义（三态，不虚高）

本项目的"判定"只出现在**导入解析**与**门控**两处，其余是计算（计算无三态）。导入解析三态：

| 状态 | 触发 | 该行是否入库 | 是否计入异常清单 |
|---|---|---|---|
| `ok` | 列名白名单命中 + 类型校验通过 | 是 | 否 |
| `invalid` | 数值越界/非数值/必填列空 | 否 | 是 |
| `unknown` | 列名未登记（`mapping_uncertain`，**表头级**） | **是**（只多了一列不认识的） | 是 |
| `unknown` | 整行结构不可解析（字段数多于表头，**行级**） | **否**（列对齐已不可信） | 是 |
| `unknown` | 单位未登记 | **是**（只提示，首期不做单位换算） | 是 |

> **两处 `unknown` 的行可用性是分开的口径**（M2 补齐时显式登记，防"都是 unknown 就都同一处置"的想当然）：表头级只是"多了一列不认识的"，已登记列照常解析；行级则是**列对齐不可信**——宁可少一行可用数据，不可把错位的值当成对的。

**红线**：`unknown` **不等于** `ok`（"没看到"≠"没有"）；异常行一律**列入清单并计数**，绝不静默丢弃后报告"导入成功"。批量导入单行异常**不中断整批**，失败件单列，退出码仍由"是否有 `invalid`/`unknown`"决定（skill 阶段 6 批量退出码纪律：**"没判定"与"判出违规"是两种不同的退出码语义**）。

### 五之二、导入层其余既定口径（M2 登记，不写就是隐性口径）

| 项 | 口径 | 理由 |
|---|---|---|
| 编码 | 只接受 UTF-8（含 BOM，按 `utf-8-sig` 读）；非 UTF-8 **显式拒绝**（exit 2） | 编码猜测会把 GBK 字节静默解成乱码品名，产出"自洽但错"的食材库，比报错危险得多 |
| 形态失败 | 空文件 / 仅空白 / 只有表头 / 缺必填列 / CSV 结构错 → **抛错**（exit 2），**不进逐行清单** | 这是整份文件的形态问题，不是某一行的问题。混进清单会误导读者去改某一行 |
| 零可用行 | 全部行判 `invalid`/`unknown` → 报错**必须指向进货单**，不得由下游报"BOM 引用了不存在的食材" | 错误指向错误的对象比沉默更坏：用户会照着提示改错文件。`check` 通路记 issue 并显式声明"已跳过 BOM 交叉核对" |
| 同品名取舍 | 食材库**取最后一条**价；`duplicate_names()` 使重复可观测，`run`/`check` 结果里显式列出 | "取第一条"与"取最后一条"都能自圆其说——不登记就会长出第二份实现（M1 快照侧 `prodName` 同日可重复已踩过） |
| 金额列 | **不校验数值性**（不参与任何计算；成本由 `数量 × 单价` 经 F1/F2 得出） | 属原始单据的留档冗余列。不校验是登记过的口径，不是遗漏 |
| 空白行 | 行间空行不产出记录（`csv` 模块行为） | 空行不是数据行；行尾换行与空行是编辑器常态，不得因此丢数据 |
| 异常清单可见性 | 摘要写"见清单"则**必须真打印清单**（`pipeline.render_issues` 单一渲染源，`run`/`check` 共用） | 同"未启用章节显式写出"：承诺可见性就必须真可见 |

## 六、报告口径（人读 + 机读双轨）

- **单一渲染源**：`src/rcc/report/sections.py` 返回结构化章节，Markdown 渲染器与 XLSX 渲染器**各自读它**——"两格式内容一致"因此是**结构性质**而非人工抽查（skill 阶段 6）。
- **机读产物逐字节可复现**：自写最小 OOXML writer（`ZIP_STORED` + `create_system=0` + 固定 `date_time=(1980,1,1,0,0,0)`），零第三方依赖；同输入两次导出字节一致。
- **无外链**：CSV/XLSX 单元格与关系项无 URL；断网可开（硬断言测试）。
- **溯源硬约束**：报告必含**参数来源块**（每项参数：来源类型 + 文件/快照标识 + 抓取日期 + 出处说明），并把**逐项计算过程**直接渲染引擎的 `steps` 留痕（报告层**不重算**，否则又是一处第二实现）。
- **"未启用"章节显式写出**：未跑预警/未跑门控时写"本次导出未启用 X（用 `--with-alert` 启用）"，**不留空**——"没查"与"查了没问题"是两种结论。

## 七、口径变更纪律

- 本文件是"动了会打挂基准"的口径来源。改动 F1–F6 任一公式、参数语义、三态定义、量化规则，**必须同步四处**：引擎实现 / 真值库（走生成器整目录重生成）/ 断言与基准 / 本文件 + plan/00 决策记录。
- **两种修正情形要分清**（skill 阶段 5）：① **校验方式不自洽**（谓词自身矛盾）→ 只改谓词，不动冻结真值；② **口径本身定错**（"该按哪条算"错了）→ **引擎与真值同源修正，两边一起改**。
- 两种情形的**共同验收门** = `tools/gen_truth.py --check` 输出 `FROZEN_TRUTH_OK`。它是"改完还自洽"的统一证据，比人肉判断硬。
