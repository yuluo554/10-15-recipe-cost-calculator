# plan/05 发布与交付

仓库 `10-15-recipe-cost-calculator`。v1（2026-10-15）。M0 定稿（设计期），M5/M6 实现后回填实测结果。

## 一、交付形态

| 形态 | 入口 | 说明 |
|---|---|---|
| CLI | `rcc`（console script） | 脚本化通路：`run` / `check` / `bench` / `selftest`，无 Python 机器上由 CLI exe 提供 |
| 桌面 GUI | `rcc gui` / GUI exe | PySide6 多页签，**只消费编排层 API，零判定逻辑** |
| 内置基准 | `rcc bench` | 五套件 + 探活，离线可跑 |
| 报告 | `rcc run --report md,xlsx` | 人读 Markdown + 机读 XLSX，单一渲染源 |

**PyInstaller onedir 双 exe**：GUI（`console=False`）+ CLI 控制台（`console=True`，与 `rcc` 同一 main）。理由：无 Python 机器的**脚本化验证通路**（selfcheck/bench/check）全可跑。

## 二、依赖分层（extras）

| extra | 内容 | 边界 |
|---|---|---|
| （core） | 纯 stdlib | 引擎/解析/基准**零第三方依赖** |
| `dev` | pytest、pyyaml（CI workflow 守门） | **测试期必需**，含全部"测试套件真 import 的库" |
| `gui` | PySide6 | 仅 GUI；缺它 `rcc gui` exit 3 |
| `build` | PyInstaller（**≥6**）、setuptools 上限钉法 | 构建期，**不进运行时必需面** |

**纪律**：
- **测试面 = 安装面**：测试套件真 import 的每个库都必须在 README 快速开始那条安装命令的 extras 里；
- **打包工具版本按"打什么"分档**：打 GUI（PySide6）**必须 PyInstaller ≥6**（5.x 确定性崩在 `Instruction object is not iterable`）；发布构建固定在"装了 ≥6 的那条解释器通道"（本机 = `py -3.12`）；
- **辅助模块别与工具链依赖同名的顶层模块**：`packaging.py` 会遮蔽 PyPI `packaging`（PyInstaller 依赖它做版本判断）→ 放**包内**（`src/rcc/packaging.py`），不放仓库顶层；
- `build` extra 显式钉 `setuptools` 上限（PyInstaller 5.x import `pkg_resources`，setuptools 81 起移除）+ 守门测试断言该钉法。

## 三、打包白名单（单一事实源）

- datas **只准由 `rcc/packaging.py` 的 `build_datas()` 产生**（白名单），spec 内**不得手写数据路径**；
- 复制**禁区段**（如版权原文 `data/knowledge/raw/`，如适用）在构建器内直接抛错；
- **构建后 `--check` 三断言**（任一违反 exit 1）：dist 全树禁区成分扫描（**只匹配 dist 顶层**——按任意层级会把依赖包自带的同名子目录当命中）+ 内嵌数据逐份 sha256 对账 + 白名单外多余检测；
- **白名单与排除项互相矛盾要自检报错**（如 `data/` 下出现未登记目录即构建失败，防"新数据目录悄悄没进包"）；
- spec 文本守门测试：断言 spec 无手写数据路径、无禁区字面。**三处守门互相独立，改一处口径必同步另两处**。

## 四、冻结态数据定位与自检

`find_data_dir()` 冻结分支优先级（**改优先级属"动了会打挂测试"的口径变更**，配分支测试锁死）：

1. 显式参数 → 2. 环境变量 → 3. `sys._MEIPASS/data`（PyInstaller 6 内嵌）→ 4. exe 目录 `_internal/data`（PyInstaller 5 兼容）→ 5. CWD 上溯。

**`--selftest`（窗口版回传形态）**：`rcc-gui.exe --selftest <输出文件>`——只需一个输出路径参数，把装配结果（页签数 / **数据目录** / 生效参数数 / 版本）写 JSON 文件、退出码携带成败。窗口版 stdout 不接终端，**这是唯一能脚本化验收窗口 exe 的通路**。

自检 JSON 必断言：
- `frozen=true`；
- **`data_dir` 落在 dist 之内**（`os.path.commonpath([exe_dir, data_dir]) == exe_dir`）——打包最常见的失效模式是"数据没随包走、exe 回头读了开发机的仓库"，本地看着能跑、换机器就废；
- 生效参数数 > 0。
- **非冻结态该项返回 `None` 而非 FAIL**（不让源码运行被误判）。

**冻结态缺依赖提示要分流**：源码态说 `pip install -e ".[gui]"`；冻结态用户装不上 → 说"本发行包未内嵌该功能"。判别 = **"这条提示在只有 exe 的机器上，用户照做能不能成？"**

**验收环境**：中立目录（`%LOCALAPPDATA%\Temp`）+ `env -i` 剥离 PATH，**别在仓库树内跑**——CWD 上溯会命中仓库 `data/`，"内嵌数据"验了个寂寞。

## 五、构建产物留底与基线校验

- **构建后必铲干净 `dist/` 再重建**（数据变更后不重建 = 产物与源码基线脱钩）；
- 构建产物**留底在仓库树外**（`_backups/release/*.zip`）——`--clean` 类构建会先删 dist，构建若因环境级崩溃失败，树外那份是唯一回退；
- 打 tag/Release 前先 `git diff <构建时的提交>..HEAD -- src/ tools/*.spec`，**非空即重建**；空则**复验一条不能省**（"没改源码"证明的是 exe 层基线，证明不了 zip 组装步骤没坏）；
- **改版本号必须重建产物**（exe 内嵌 `__version__`，不重建则附件里 `selftest` 仍报旧版本）；
- 产物 sha256 留档**由 `sha256sum`/`hashlib` 输出直接重定向生成，人只写注释行**（手工转录 64 位 hex 错一位肉眼不可查）；沿用 `plan/DIST-sha256-M<n>.txt` 格式，发布前对同名产物跑一次跨留档 diff。

## 六、发布 zip 确定性（"可复跑的是哪一步"要写清）

Release 附件用 **ASCII 名 zip**（跨平台解压友好、避开 `gh` CLI 剥中文名），打包用 Python `zipfile` 手打：

- `ZIP_STORED` + 条目**按路径显式 sort**（`os.walk` 顺序跨调用不稳定，实测不排序则两次打包字节不同）+ 全条目固定 `date_time=(1980,1,1,0,0,0)` + `create_system=0`；
- **两次独立打包逐字节一致**（实测背书）；
- 留档写清：**可复跑的是"同 dist → 同 zip"这步**；**exe 构建本身不承诺跨机字节一致**——别把 exe 哈希也写成可复现；
- 台账工具化：`rcc release-ledger` 输出 JSON（附件名 / sha256 / 字节数）供 RELEASE-M6 直接引用，避免手抄漂移。

## 七、CI 与 EOL 门（M0 即配，别推迟到发布期）

**反模式**：把建仓推迟到发布里程碑 = 把全项目 CI 首跑风险压进发布窗口。**M0 即配齐**，首跑只是验收。

- **EOL 门**：`.gitattributes` 写 `* text=auto eol=lf`；**被台账登记过 sha256 的快照**（官方/抓取原始件）标 **`-text`** 防 EOL 改写字节；配"冻结 fixtures 出现 CR 即大声失败"的守门测试。
- **CI 矩阵**：`windows×{3.8,3.12} + ubuntu×{3.12}`（旧解释器只在 windows 守；跑完按实况记录，不硬凑四矩阵）。
- **CI 配置**：`env: PYTHONUTF8=1 / PYTHONIOENCODING=utf-8`；每个 checkout 配 **`fetch-depth: 0`**（历史扫描类守门依赖 git 历史，浅克隆会**静默削弱成空验**）；**CI 的 extras 集合必须覆盖"所有里程碑门的依赖"**（否则门在 CI 上静默跳过，"本地一直绿"≠"CI 验过"）。
- **守门**：G-CI 断言全部 workflow 可解析且每个 job 有 `runs-on`/`steps`（非法 YAML 会让 GitHub **不建任何 job**，而 state 仍显示 active、字节也洁净——看状态、看字节都查不出）。
- **GitHub 建仓路径**：本机 token scopes = `gist, read:org, repo`（**无 workflow**）→ `gh repo create --public --description ... --source . --remote origin`（**不带 `--push`**，否则含 workflow 文件必被拒、留下半失败态）→ 验证 SSH key → `git remote set-url origin git@github.com:<u>/<r>.git` → push 一次成（**SSH 不受 OAuth scope 限制**，携带 workflow 文件 GitHub 正常识别并触发 CI）。
- **对账口径**：`gh run list` 按**提交逐条配对**（`head_sha` + `conclusion` 与本地 `git log` 对齐）；**对账单位是 push 事件**，不是提交数；tag push 是否触发一轮**以当轮实测为准留档**（两种行为都出现过）。

## 八、脱敏发布（M6 执行，四步 + 产物扫描）

本机环境事实（M0 实测）：`git config user.email = <真实 QQ 邮箱>`，`core.autocrlf=true`。**真实个人邮箱必须全历史改写**。

1. **文件级**：`git ls-files` 无 `.env`/`.key`/`secret`/`token`；`.gitignore` 覆盖 `.env`/运行产物/`_private/`；
2. **内容级**：全部跟踪文本文件扫 `sk-` 密钥、密钥赋值、手机号、身份证、个人路径、内网 IP、邮箱；
3. **提交元数据**：`git log --format="%ae %ce" --all | sort -u` 单独检查——**内容级扫描不覆盖 git 元数据**。真实邮箱 → **`git filter-repo`**（首选，自带清理；filter-branch 的 if/elif 只改一半、annotated tag 不重写、SIGPIPE 坏 ref、MSYS 路径四坑全部不适用）改写为 GitHub noreply（id 取 `gh api user --jq .id`），本地 `git config user.email` 同步改；改完 **`git log --format='%ae %ce'` 只剩 noreply 一个值**；
4. **历史终验三扫**（全 0 才算过）：`git rev-list --all` 逐提交 `git grep`；`git log --all -p | grep -c`；提交信息扫描。**扫描前先跑阳性对照**（已知存在的字面值）验证扫描命令本身有效——多 rev 的 `git grep` 会静默 0 命中造成"全历史干净"假绿；
5. **构建产物本体扫描**：全 dist 树 Python 字节读法跑强标记（个人标记按**组合路径签名** `Users\<名>` 匹配，不匹配裸词——否则 Qt DLL 里的厂商串含本机用户名子串会刷屏）；产物扫描绑"**我们的工作根**"组合签名，防上游二进制构建机路径误报；命中串的豁免裁决 = **"官方原件同串比对"**（同串存在于官方发行件原件 = 上游固有，逐条留档判定依据）；**留档与扫描器源码不得逐字复述命中串**（掩码/拼接形式）。

**扫描器固化形态**：`tools/audit_desensitize.py` 四模式（tracked / history / messages / dist）+ `--selftest` 阳性对照；**禁用 token 全部运行时实算**（邮箱数字串从 `git log` 实算、用户名从 `getpass.getuser()` 实算、盘符从仓库绝对路径实算），**源码与留档零词面**——门禁自己的输入也不许是代码字面量。输出**一律掩码化**，命中分级 **HARD（exit 1）/ REVIEW（人工豁免留档）/ advisory（只报不阻断）**，支持行内 `audit-allow` 放行标记（放过项仍打印，不静默吞）。

**豁免口径写死**：GitHub 账号名（克隆 URL 两种形态 HTTPS+SSH 必含）= 发布固有公开元数据；`*@users.noreply.github.com` = 已脱敏的目标形态；`git@github.com` = 服务传输地址非个人邮箱。**豁免项也要进 selftest 阴性对照**。

**时序纪律**：
- **收官期新增文档（发布留档/交接快照）先 `git add` 再跑本地审计**——tracked 扫描面只含已跟踪文件，"本地审计绿"≠"未 add 的新文档干净"；
- **留档措辞本身要过扫描**：写"用户目录签名 / 本地工作根签名"这类**描述性指代**，不复述路径形式；**"验证描述"是最高频的自命中源**（写"用固定字面值 X 扫描得 0 命中"时 X 本身进了仓库 → 写成"用固定字面值（不在此复述）扫描得 0 命中"）；
- **CI run 日志是第三个留档面**：守门失败会回显待检文档原文行 → 含敏感回显的失败 run 必须 `gh run delete`；转公开前逐 run 核查日志；
- **未推送窗口是历史修正的零成本期**：发现未推送提交带污染 → `git reset --soft <污染前>` 软重置成干净提交，**别等推了再 filter-repo**。

## 九、发布前"三清"（转公开的时序门）

切 `--visibility public` **之前**必须三清：① 全历史脱敏审计三扫 0 硬门；② 历史坏 blob 已修净（`git fsck` 无悬空敏感对象）；③ 失败 run 已删。**先清后切是单向门，顺序反了代价一个量级**。可见性决策落 plan/00 决策记录（用户定夺 + 日期）。

### 九之二、快照类字节冻结件的打包纪律（M1 实测补充）

`data/snapshots/` 与 `data/truth/` 是**台账登记过 sha256 的字节冻结件**，比一般 fixtures 更严：

- **`.gitattributes` 必须标 `-text`**（`data/snapshots/** -text`），否则 `core.autocrlf=true` 的机器检出时把 LF 翻 CRLF → sha256 失配、`--check` 全线报红；
- **"标了 `-text`"不等于"字节真没变"**：M1 实测做法 = `git add` 后比对工作树 sha256 与 `git cat-file blob :<path>` 的 sha256，**逐份相等**才算冻结生效（`git check-attr` 只证明属性被声明，证明不了字节）；
- **冻结件走抓取器/生成器产出，禁手改**；人读说明（如快照 `README.md`）也由生成器**同源渲染**——手改说明即被 `--check` 检出，防"说明与台账漂移"；
- **打包白名单**：`rcc/packaging.py` 的 `DATA_WHITELIST` 已含 `data/snapshots`；新增数据目录必须同步登记，否则构建后断言报"白名单外多余"。

## 十、发布留档三件套（M6 DoD，缺一即未达成）

1. `git tag -a vX.Y.Z`（**打在含完整收尾回写文档的提交上**）+ push tag；
2. `gh release create` 附产物（本地留 release zip 副本 + sha256 留档可复验）——**notes 用 `--notes-file <md>` 传文件**（表格/换行安全）；加 `--verify-tag`；发布后 **`gh release view <tag> --json assets,tagName,isDraft`** 核验（`draft=false` + 附件名在列才算闭环，`gh` 上传偶发半失败）；**移动已发布 Release 的 tag 会把它打回 draft**，每次移动后必须复验 `isDraft`；
3. `plan/RELEASE-M6.md`（发布留档，只写**实测到的**，未跑的项留 ⬜ 并说明原因，不留空不预填）。

**发布物本体验证**（最强证据）：真下载 release 附件 → 下载件 sha256 与留档逐位一致 → 解压中立目录跑冻结态自检（`--selftest`）。三步齐了才算"发布物本体已验"。

## 十一、README 终检

根 README 必含：简介 / 特性 / mermaid 架构图 / 快速开始 / 评测表 / 目录 / **限制** / 免责声明 / **已知环境问题** / **下载即用**（Release 附件名与实际上传的 ASCII 名一致 + 校验命令）+ LICENSE。

- **状态行转正**：发布后把"🚧 准备中"改"✅ vX.Y.Z 已发布"（挂 Release 链接）；
- **CI 徽章**指向发布仓库 Actions；
- **"逐字执行 README 链"是常驻回归门**（G-README）：README 引用的每个输入文件必须**由生成器/版本控制保证存在**——本地工作目录残留会掩盖"引用了根本不存在的文件"，且 **CI 也暴露不了它**（CI 只跑 pytest 不读 README）。
